# Module 4: Timing Analysis, Clock Tree Synthesis & Physical Design

## 📌 Project Overview:

This project focuses on the physical-design and timing-analysis stages of an RTL-to-GDSII flow using the PicoRV32A design, OpenLane, OpenROAD, and the SKY130A technology.

The module covers:

RTL Design → Synthesis → Cell Mapping → Floorplanning → Placement → Clock Tree Synthesis → Timing Analysis → Routing → Physical Verification

The project also studies important timing concepts such as:

* **Setup time**
* **Hold time**
* **Data arrival time**
* **Data required time**
* **Slack**
* **Clock skew**
* **Clock latency**
* **Clock-tree buffering**
* **Crosstalk-induced delay**
* **Real-clock timing**
* **Ideal-clock timing**

The main objectives of this project are:

## 14. Crosstalk Delta Delay and Clock Skew:

This image explains the effect of **crosstalk-induced delta delay on clock skew.**

Coupling capacitance between neighbouring wires can change the delay of a signal.



Before Crosstalk
Delay = D

with:

After Crosstalk
Delay = D + Δ

The diagram further represents the relationship:

L1 = L2 + Δ

and:

SKEW = L1 − (L2 + Δ)

Crosstalk therefore has the potential to change signal delay and consequently affect clock skew.

This is particularly important in advanced physical-design timing analysis where interconnect effects become significant.

**📊 Important Timing Concepts:**

**Setup Time**

Setup time is the minimum amount of time for which input data must be stable before the active clock edge.

Data must arrive sufficiently before:
                    ↓
                Clock Edge

A setup violation occurs when the data arrives too late.

**Hold Time**

Hold time is the minimum amount of time for which data must remain stable after the active clock edge.

Clock Edge
    ↓
Data must remain stable

A hold violation occurs when data changes too soon after the clock edge.


**Data Arrival Time**

Data arrival time represents the time at which data reaches the capture element.

It depends on:

* Cell delay

* Interconnect delay

* Buffer delay

* Routing parasitics

**Data Required Time**

Data required time represents the latest acceptable arrival time for the data to satisfy the timing constraint.

**Slack**

Slack represents the difference between the required and actual timing.

For setup analysis:

Slack = Data Required Time − Data Arrival Time

Generally:

Positive Slack → Timing requirement satisfied
Zero Slack     → Critical timing boundary
Negative Slack → Timing violation

# ⏱️ Real Clock vs Ideal Clock

| **Parameter**      | **Ideal Clock**            | **Real / Propagated Clock** |
| ------------------ | -------------------------- | --------------------------- |
| Clock network      | Idealized                  | Physically implemented      |
| Clock buffer delay | Not fully represented      | Included                    |
| Clock skew         | Idealized                  | Included                    |
| Wire RC delay      | Simplified                 | Included                    |
| CTS effects        | Not represented completely | Represented                 |
| Timing accuracy    | Preliminary                | More realistic              |

The major objectives are:

Reduce clock skew

Maintain acceptable slew
Handle capacitive load
Distribute the clock efficiently
Satisfy setup and hold requirements

## 🧮 Timing Closure

Timing closure is the process of modifying the physical implementation until the design satisfies its timing constraints.

Typical optimization techniques include:

1. Cell sizing

2. Buffer insertion

3. Buffer resizing

4. Placement optimization

5. Clock-tree optimization

6. Routing optimization

7. Reduction of excessive wire delay

8. Reduction of clock skew

9. Optimization of critical paths

The final objective is to obtain timing results with acceptable slack for all required paths.
